<objective>
Make `MassiveDataSource.history` safe to call for every watchlist ticker at page load on the Massive free tier (06-UAT.md test 3).

Design (chosen as the simplest that works): keep `GET /api/history/{ticker}` as the only history API and throttle inside the source. One `asyncio.Lock` serializes uncached fetches; in `eod` mode each `get_aggs` call waits until `HISTORY_SPACING` (15 s) has passed since the previous one. 15 s = 4 calls/min, leaving one call/min of the 5/min free-tier budget for the EOD poll and `add_ticker`. A cache hit is checked before taking the lock, so cached tickers (and page reloads) are instant. Re-checking the cache inside the lock makes concurrent requests for the same ticker single-flight. Rejected alternatives: a startup warm-up task (extra lifecycle code, same fill time) and serving history inside `/api/watchlist` (needs a separate fill mechanism plus client polling). The frontend (plan 06-10) requests sparkline seeds one ticker at a time, so a waiting request occupies only one browser connection.

Purpose: failed fetches are not cached, so unthrottled per-row calls left about half the rows empty.
Output: throttled history in massive_source.py, constant in massive_parse.py, new tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> POST /api/watchlist | untrusted JSON body (ticker) enters the backend for the first time |
| browser -> DELETE /api/watchlist/{ticker} | untrusted path parameter |
| backend -> SQLite file | DB_PATH from deployment env |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | app/db.py SQL | mitigate | All queries use `?` bound parameters; acceptance grep forbids f-string SQL |
| T-02-02 | Tampering | AddTicker validator | mitigate | strip + upper + `re.fullmatch(r"[A-Z]{1,5}")`, else 422; test_invalid covers "TOOLONG", "A1", "", "BRK.B" |
| T-02-03 | Tampering | DELETE path param | mitigate | normalized with strip/upper and used only as a bound parameter; unknown value -> 404, no source call |
| T-02-04 | Denial of service | event loop | mitigate | every sqlite call via asyncio.to_thread; connection per call |
| T-02-05 | Denial of service | unbounded watchlist adds | accept | single local user, simulator cost per ticker is tiny; no cap this phase |
| T-02-06 | Information disclosure | DB_PATH env | accept | trusted deployment configuration, not user input |
| T-02-07 | Information disclosure | db/finally.db, -wal, -shm in git | mitigate | .gitignore covers db/*.db, db/*.db-wal, db/*.db-shm |
</threat_model>
